---

Plain JavaScript with JSDoc types, no bundler. Electron loads `main/main.js` directly; the shell UI loads from this folder over the private `acc://shell/` protocol, which serves `renderer/`, `shared/`, and the two xterm packages from `node_modules`, and nothing else. Every path in the shell UI is relative, so the same files also serve from a subpath on GitHub Pages as the demo (`demo/`, below).

## 🖥️ main/ — the main process

| File | What it does |
|:---|:---|
| [**main.js**](main/main.js) | The app's wiring. Switches to the profile `ACC_USER_DATA` names (the smoke run's throwaway one) before the single-instance lock, creates the window and the shell view, serves `acc://shell/`, denies pages every permission not in `shared/permissions.js`, and hooks the crash log. Registers every IPC channel, each refusing any sender but the shell's main frame on `acc://shell`, and builds the app menu with its shortcuts. Holds the workspaces: which is active, saving its tabs and terminal folders, and a switch that closes one set of tabs and opens the other's. Starts the MCP server and hands its tools the tabs, Hub, Recent and the terminals; for `terminal_run` and `cron_run` it holds the pending asks and fixes each command's folder when it asks; on Run it opens the run's own session and keeps the run list (`shared/runs.js`) that `run_status` reads, and closing a running run's terminal cancels it. Each ask also goes into the activity list (`shared/activity.js`) the MCP panel shows. Runs `npm run smoke` when `ACC_SMOKE_DIR` is set and exits with its verdict. |
| [**tabs.js**](main/tabs.js) | Browser tabs: one sandboxed `WebContentsView` each, sized to the rectangle the shell reports. Blocks `javascript:` and other schemes, turns links and plain `window.open` into tabs but lets a real pop-up (window features, as sign-in flows use) open as its own window so `window.opener` survives, owns the page context menu, keeps the last 10 closed URLs for Reopen closed tab (a workspace switch closes every tab without filling that list), zooms, finds in the page and reports the match count, and reads a page's visible text for `read_tab`. Holds the one tab attached for agents (its right-click menu's checkbox) and runs `pageactions.js`'s scripts there in an isolated world: the element list, a screenshot, and after the confirm bar a real mouse click or `insertText`. |
| [**adblock.js**](main/adblock.js) | Loads Ghostery's prebuilt ads-and-tracking engine, cached in userData and refreshed weekly. `main.js` turns it on for the browse session and owns the menu toggle. |
| [**extensions.js**](main/extensions.js) | electron-chrome-extensions and the Web Store installer on the browse session, and the app menu's Extensions submenu (Web Store, options, remove). See [ADR-001](../docs/decisions/adr-001-electron-shell.md). |
| [**terminal.js**](main/terminal.js) | Shell sessions through node-pty. The renderer picks a folder and a profile from `shared/shells.js`, where executables and arguments are fixed. Reports each session's shell, folder and state. A `terminal_run` run is a session main opens with `runShell()` and the command in `ACC_RUN_COMMAND`; its exit goes to `onExit`, and closing it ends its process tree (`kill.js`). keeps the newest 200,000 characters of each session's output for `terminal_read`, looks for installed shells again when Connections asks, and which session the panel shows. Each session is tagged with the workspace it opened in, so a switch can hide it without stopping it. See [ADR-003](../docs/decisions/adr-003-terminal-in-main.md). Every session gets its environment from `env.js`'s `childEnv`, without the chat key, plus `ACC_MCP_URL` and `ACC_MCP_TOKEN` once the MCP server is up, so `claude` in it can reach the app. |
| [**docs.js**](main/docs.js) | Serves `acc://doc/<Hub id>` on the browse session: Hub's `/api/file` HTML wrapped in a script-free page, folder listings, and images read from disk for document pages only. Only ids in Hub's index. Hands `acc://run/…` to `cronsole.js`, `acc://git/…` to `git.js` and `acc://dev/…` to `devservers.js`, refusing any request with a referrer but another page of the same kind. The index is invalidated on Hub's `change` events. |
| [**hub.js**](main/hub.js) | The Project Hub client, each request read inside a 30 s deadline: health, scan, bookmarks, favorites (read and star-toggle through `PUT /api/favorites`, one toggle at a time), file, open, and the `/api/events` subscription that reloads the tree and drops the doc index when Hub rescans. See [ADR-002](../docs/decisions/adr-002-hub-over-http.md). |
| [**chat.js**](main/chat.js) | The chat panel's open conversation: reads the key and model from the environment at each send, reads + page and + terminal through the MCP server into the context tray and keeps those snapshots until the next message sends them (or Clear or a workspace switch drops them), gets the tools from the MCP server, runs the turn from `shared/chat.js`, and sends each step to the shell, streamed text included. Loads the open conversation at start and whenever the workspace or the open conversation changes (never while a turn runs), hands the panel its transcript, and saves after every turn through `main.js`, which keeps the workspace's conversation list. Stop aborts the turn in flight. The key never leaves the main process. |
| [**mcp.js**](main/mcp.js) | Starts the Control Center MCP server, with the tools from `shared/tools.js`, on `127.0.0.1` with a random port and a per-launch token, writes both to `mcp.json` in `%APPDATA%\ai-command-center`, and removes the file on quit. It hands back the URL and token for the terminals. `mcpLog()` keeps the newest 200 calls for the sidebar and appends every call to `logs\mcp.log` through `applog.js`, with `terminal_run`'s command as its length only. |
| [**applog.js**](main/applog.js) | Append-only log files under `logs\`, rotated at 5 MB, and the crash log: uncaught errors and rejections in the main process, and renderer, tab or helper processes going away, written to `app.log`. |
| [**cronsole.js**](main/cronsole.js) | Cronsole's MCP server as a child process: this app's Electron binary in Node mode running the script `ACC_CRONSOLE_MCP` names, started on first use, started again after it exits, killed on quit. Answers the sidebar and `cron_tasks` with `list_tasks`, a task's runs with `get_task_history`, an `acc://run` page with the run's log or `get_run_output` (a task in the list and a run in its history only), and `cron_run` with `run_task` once the user has clicked. |
| [**git.js**](main/git.js) | The Git tab's git calls, read-only: the workspace's repo and its status, and one file's diff as an `acc://git` page, refused unless git lists that file with that kind of change. Command lines come fixed from `shared/git.js` and run through `execFile` with `childEnv`. |
| [**devservers.js**](main/devservers.js) | The Dev tab's servers: `<npm\|pnpm\|yarn> run <script>` for a dev script in the workspace's `package.json`, through cmd by the manager's full path, with `childEnv`. Keeps each one's output, the address it printed and its state; Stop and Restart end its process tree by the pid `spawn` returned, only while it runs; `stopAll()` at window close. Serves `acc://dev/<id>` log pages. |
| [**kill.js**](main/kill.js) | `killTree()`: `taskkill /T /F` on a pid the app started, for dev servers and cancelled runs. |
| [**env.js**](main/env.js) | The app's configuration: `.env` under the real environment, kept out of `process.env`, and `childEnv()`, the one place a child process's environment is built (the chat key dropped under either name), and `onPath()`, a program's full path from PATH's absolute entries. |
| [**smoke.js**](main/smoke.js) | `npm run smoke`'s checks, run inside the app: each a named PASS, FAIL, SKIP (needs `--live`) or WARN, written to `summary.json`, with the exit code set from them. |
| [**store.js**](main/store.js) | `recent.json`, `layout.json` (splitter sizes, terminal and chat pane open or not, bookmark source, ad blocking), `workspaces.json` (read through `shared/workspaces.js`; its first read takes the tabs an older `layout.json` saved), each workspace's conversations (`chats/<ws>/index.json` read through `shared/conversations.js`, and one file per conversation read through `shared/chat.js`'s `cleanMessages`; the first read moves an old `chat.json` or `chat-<id>.json` in) and `settings.json` (read through `shared/settings.js`) in `%APPDATA%\ai-command-center`, written atomically. |

## 🔌 preload/

| File | What it does |
|:---|:---|
| [**shell.cjs**](preload/shell.cjs) | Exposes `window.acc` to the shell UI only, and registers `<browser-action-list>` for extension toolbar icons. Browser tabs get no preload from this app but the extension-API ones, which act only on `chrome-extension://` pages. |
| [**extension-browser.cjs**](preload/extension-browser.cjs) | In extension pages and service workers only, points `browser` at the `chrome` object electron-chrome-extensions fills in, so MV3 extensions that prefer `browser` find `windows`, `cookies` and the rest. See [ADR-001](../docs/decisions/adr-001-electron-shell.md#update-2026-10-20-the-browser-namespace). |

## 🎨 renderer/ — the shell UI

| File | What it does |
|:---|:---|
| [**index.html**](renderer/index.html) | The layout: sidebar, splitters, tab strip, address bar with the find bar, content area, terminal panel, and the chat pane on the right. Strict CSP. |
| [**app.js**](renderer/app.js) | Wires everything together: the workspace menu at the top of the sidebar, the command palette's entries and the actions it shares with the menu shortcuts (`runAction`), tab strip and address bar, the chat pane (💬, Ctrl+Shift+L, its splitter), the address-bar ☆ that adds the page to Hub's favorites, splitter drags, shortcuts, the confirm bar for `terminal_run` and `cron_run` (one ask at a time; Deny has focus), the find bar (Ctrl+F, match count, Enter and Shift+Enter, closes on tab change), the shell menu on the terminal strip, opening documents in a tab (reusing one already showing a document; Ctrl+click for another), the pinned Cronsole tab (first in the strip, no close button, reused by Open Cronsole), and reporting the content rectangle so the active tab sits exactly over it. |
| [**chat.js**](renderer/chat.js) | The chat pane on the right: shows the conversation as plain text (messages, each tool call and its result), grows Claude's reply as the text streams in, replays the open conversation, lists the workspace's conversations under the name at the top (search, open, rename, two-click delete, New), keeps the context tray (+ page and + terminal add a row with the exact text that will go, ✕ drops it, sending sends those rows), and says which variables to set when the key or model is missing. |
| [**connections.js**](renderer/connections.js) | The Connections dialog: one row per group (Hub, Cronsole, shells, chat, MCP), each checked on its own so a slow one doesn't hold up the rest, with a Retry per row. Opened from the sidebar's status dot, the palette and the menu. |
| [**palette.js**](renderer/palette.js) | The command palette (Ctrl+K): a native `<dialog>` with a box and a list, keyboard and mouse picking, the browser tab hidden while it shows. `app.js` hands it the entries (actions, workspaces, tabs, terminals, and Files matches once something is typed), each with what it does. |
| [**sidebar.js**](renderer/sidebar.js) | Files, Bookmarks and Recent panels and the search box across them, plus the MCP panel of what agents asked to run and how it went (Agent work, counted on the tab's label), the searchable run history, and the calls they made, the Cron panel of Cronsole's tasks, the Git panel of the workspace repo's changes, and the Dev panel of its dev servers (the chat has its own pane), where a click unfolds a task's last runs and a run opens its output page. Clicks, hover buttons and the right-click menu on Files rows all go through one `fileAction()`. The Files tree starts at the active workspace's folder and reloads when Hub reports a change. |
| [**terminal.js**](renderer/terminal.js) | One xterm.js instance per shell session, only the active workspace's tabs showing, with copy and paste keys and a link provider that opens web addresses in the output as tabs; tells main which session is showing, so `terminal_read` reads that one by default. |
| [**styles.css**](renderer/styles.css) | Dark theme and the grid layout. |

## 🎭 demo/ — the browser demo

The shell UI from `renderer/` running in an ordinary browser. `npm run demo` (`scripts/demo.js`) copies `renderer/`, `shared/`, this folder and xterm into `_site/`, and `.github/workflows/pages.yml` deploys that to [houston-demo.ai-automation-tools.dev](https://houston-demo.ai-automation-tools.dev/) on every push to `main`. The app never loads anything here.

| File | What it does |
|:---|:---|
| [**acc.js**](demo/acc.js) | `demoApi()`: every call `preload/shell.cjs` exposes, answered from made-up files, bookmarks, Cronsole tasks and MCP calls. Tabs keep a history but have no browser behind them; terminals echo what you type and answer `npm test`, `git status`, `ls` and `help` with canned output; one `terminal_run` ask shows the confirm bar after six seconds; the chat streams one canned reply. No network, no storage. |
| [**install.js**](demo/install.js) | Loaded before `app.js`: puts `demoApi()` on `window.acc`, draws the stand-in page where a tab would be, shows toasts, and turns Ctrl+K into the palette shortcut the app menu gives the real app. |
| [**about.js**](demo/about.js) | The welcome page the demo opens on: what the app is, what to try, the quick start. Static HTML, no scripts. |
| [**page.js**](demo/page.js) | `demoHtml()`: the app's `index.html` with the org source bar at the top, the demo stylesheet and `install.js` added; fails if `index.html` moved an anchor it relies on. |
| [**demo.css**](demo/demo.css) | The fixed source bar (the shell is shortened by its height), the stand-in page and toasts. |

## 🔁 shared/ — pure helpers, unit-tested

| File | What it does |
|:---|:---|
| [**tree.js**](shared/tree.js) | Hub node ids to paths, what a click on a node does, the right-click menu items, flattening a 35k-node tree without recursion, ranked search, and `searchAll`, the one search across files, bookmarks and recent that the sidebar and `sidebar_search` share. |
| [**url.js**](shared/url.js) | Address-bar text to a URL (paths, loopback, hosts, search) and the allowed navigation schemes, with `acc://doc` allowed only from the app or another document, `acc://run`, `acc://git` and `acc://dev` from the app only, and `file:` from the app or another local file (never a web or extension page). |
| [**conversations.js**](shared/conversations.js) | A workspace's conversation list: cleaning `index.json`, a name from the first message, a new one listed on its first message, rename, remove, and search (every word in the name or the text, attachments left out, with a snippet). |
| [**git.js**](shared/git.js) | The Git tab's fixed command lines (fsmonitor, external diff and textconv off), `git status --porcelain=v2` parsed into a branch and files, `acc://git` addresses, and a diff as classed lines. |
| [**devservers.js**](shared/devservers.js) | The Dev tab's rules: which `package.json` scripts count as dev servers, plain script names, the package manager from the lockfile, the first loopback address in a server's output, a state in a few words, and `acc://dev` addresses. |
| [**connections.js**](shared/connections.js) | The Connections rows: Hub, Cronsole, each known shell, the chat model and the MCP server, as working, not set up or failing, with what to set. The chat row never claims the key works. |
| [**palette.js**](shared/palette.js) | The command palette's matching: every word in the label or detail, label matches first, then a label that starts with the first word, then by kind and length. |
| [**recent.js**](shared/recent.js) | Adding to and cleaning the Recent list. |
| [**mcp.js**](shared/mcp.js) | The MCP server itself: JSON-RPC over Streamable HTTP with plain JSON replies, bearer-token, loopback-Host and loopback-Origin checks, both eras of MCP (`checkRequest` tells a `2026-07-28` request, with its `_meta` and mirrored headers checked, from an `initialize`-era one; `mirrorHeaders` builds those headers for the stdio bridge), `initialize`, `server/discover`, `ping`, `tools/list` (with each tool's `annotations`) and `tools/call`, with malformed requests answered as JSON-RPC errors and `structuredContent` only for JSON objects. A client that disconnects mid-call aborts the tool's signal. `initialize` hands out an `Mcp-Session-Id` that only names the client on its later calls. No Electron, so the tests run it for real. Reports every request, refused ones too, through an `onCall` hook. |
| [**chat.js**](shared/chat.js) | The chat's turn loop: the key and model from the environment (no default model), MCP tools in the Messages API's format, a JSON-RPC client for the app's MCP server (MCP `2026-07-28`, named `houston-chat`), the API call with streaming on and the server-sent events put back into a reply (`readStream`), trimming whole turns from the front past a 50,000-token estimate (`trimHistory`), checking a saved `chat.json` (`cleanMessages`) and turning it back into what the panel shows (`transcript`), how a context-tray row reads (`trayItem`), the attachments wrapped in `<attached …>` blocks above the text, and one turn of post, run the tools Claude asks for, post the results, at most 10 rounds. One abort signal per turn (Stop) reaches the model request and every tool call, with 5- and 6-minute deadlines; a stopped turn answers its open `tool_use`s so the next message is valid. |
| [**mcplog.js**](shared/mcplog.js) | The MCP call log's entries: method, tool, clipped arguments with URL query strings cut, success, time, error or refusal status, the client each call came from (`initialize`'s `clientInfo`, a modern request's `_meta`, or its session's), and handshake notes (the 400 and 405s that steer a client, logged as successes); the JSON line written to `mcp.log`, where `terminal_run`'s command is its length only; and the capped newest-first list. |
| [**tools.js**](shared/tools.js) | The MCP tools: read-only `list_tabs`, `read_tab` (a tab's visible text, clipped), `sidebar_search`, `recent`, `list_terminals` and `terminal_read` (the last lines of a session, cleaned by `output.js`); navigation `open_tab` (address-bar text, http and https only) and `open_file` (Hub node ids only, VS Code or reveal, never default-app); `terminal_run` (one line, no control or invisible characters, an optional drive-path `cwd`, a managed run in its own terminal only after a click, answering with a run id) and `run_status` (its state, exit code and output); `cron_tasks` and `cron_run` (a Cronsole task id, run only after a click); `tab_elements`, `tab_screenshot`, `tab_click` and `tab_fill` on the attached tab (the last two only after a click). Each carries MCP `annotations` (read-only, destructive, open-world hints). The main process passes in the data sources and actions. |
| [**output.js**](shared/output.js) | Terminal output for an agent: a one-line cell model that resolves ConPTY's cursor moves and erases into what the screen shows, drops the other escapes and control characters, the last N lines, and the capped buffer the main process keeps per session. |
| [**settings.js**](shared/settings.js) | `settings.json` with neutral defaults: the Project Hub URL (`ACC_HUB_URL` wins) and the empty-tab quick links, http(s) only. Hub must be on this machine unless `ACC_HUB_REMOTE=1`. |
| [**permissions.js**](shared/permissions.js) | The three permissions a page may be granted (fullscreen, pointer lock, sanitized clipboard writes); everything else is refused. |
| [**confirm.js**](shared/confirm.js) | Pending questions to the user: each ask gets an id, settles once with the answer, or with null after a timeout or when its asker goes away, and the UI is told to drop it. |
| [**pageactions.js**](shared/pageactions.js) | Browser actions on the attached tab: the page scripts that list its visible links, buttons and fields and, for a click or fill, check the element is still the one listed and uncovered (stringified into an isolated world), the list cleaned, the element as the bar names it, and `tab_fill`'s text checked. |
| [**activity.js**](shared/activity.js) | The MCP panel's Agent work: one entry per `terminal_run`, `cron_run`, `tab_click` or `tab_fill` ask, what was asked and its folder, task id or page host, from waiting (the one on the bar, the rest queued) through running to how it ended (the run's exit code, cancelled, denied, not answered, withdrawn, or handed to Cronsole); the newest 50 kept, open ones never dropped. |
| [**runs.js**](shared/runs.js) | Managed runs: the fixed `RUN_SCRIPT` a run's PowerShell starts with and its exit-code rule, and the run list (start, end on the session's exit code, cancel, the newest 50 kept with the end of their output), cleaned from `runs.json` at start. Also the history's search rows, the files a run changed from two `git status` lists, and the `acc://runlog/<id>` address. |
| [**shells.js**](shared/shells.js) | The shell profiles (PowerShell 7, Windows PowerShell, Command Prompt, Git Bash): fixed executables and arguments, only those installed, picked by id. |
| [**docs.js**](shared/docs.js) | Document pages: `acc://doc` URLs that mirror Hub ids (so relative links resolve), the page wrapper and its headers, folder listings, image types, and the pages around a Cronsole run's output, a Git diff and a dev server's log. |
| [**events.js**](shared/events.js) | Project Hub's `/api/events` server-sent stream, parsed from bytes: `change` events and their data, the `retry` preamble and heartbeats ignored, events and multi-line data split across chunks handled. |
| [**favorites.js**](shared/favorites.js) | Starring the current page: whether a URL is already in Hub's favorites tree, and adding it to (or removing it from) the Favorites bar, non-web URLs ignored. |
| [**links.js**](shared/links.js) | Web addresses in a line of terminal output for the terminal's link provider: `http(s)://` URLs and bare `localhost`, `127.0.0.1` or `[::1]` with a port, trailing punctuation dropped, brackets the link opened kept. |
| [**menu.js**](shared/menu.js) | Checks the item list the shell sends for a native context menu. |
| [**cronsole.js**](shared/cronsole.js) | Cronsole: the server path and UI origin from the environment, which tab URLs are the pinned Cronsole tab, a JSON-RPC client over stdio (newline-delimited, partial lines buffered, timeouts), the MCP handshake, `list_tasks` with its result cleaned into rows, `run_task` with its id checked, `get_task_history` and `get_run_output`, `acc://run` URLs, and how a task or run row reads in the sidebar. |
| [**workspaces.js**](shared/workspaces.js) | `workspaces.json`: a version, the active workspace, and the list, each with a name, a drive folder, its Hub node id, its saved tabs and terminal folders. Cleaning the file (Default always first, bad entries dropped, capped), adding one for a folder (an id from its name, the same folder found again), removing one (never Default), saving one's tabs or terminals, and its conversation's file name. |
| [**session.js**](shared/session.js) | Cleaning a saved tab list, picking which restored tab to activate, and the next, previous or numbered tab for the keyboard shortcuts. |
