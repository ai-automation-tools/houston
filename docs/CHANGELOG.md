## Unreleased

Everything since 0.1.0, newest first within each group: Phase 2 (done 2026-10-04), the public-release gates (all closed 2026-10-18, when the repo went public), Phase 2b, the Integrations, Milestone A (2026-10-20), Milestone B (2026-10-21), and the starts of Milestones C and D.

**Added**

- **Every MCP call names its client:** a client on the `initialize` handshake now gets an `Mcp-Session-Id`, used only to tie its later calls to the name it gave (it grants nothing, and an unknown id is ignored); a `2026-07-28` client is named from each request's `_meta`. The MCP tab shows the name beside each call's time, the stdio bridge carries the session id, and the chat panel's calls read `houston-chat`. *(Milestone D)*
- **MCP `2026-07-28`:** the server now speaks the current revision beside the `initialize`-era ones. A request carrying `io.modelcontextprotocol/protocolVersion` in `_meta` is served without a handshake: its `clientCapabilities` must be there and the `MCP-Protocol-Version`, `Mcp-Method` and (for `tools/call`) `Mcp-Name` headers must match the body, or it gets 400 with `-32602` or `-32020`; an unknown method gets 404; each result carries `resultType` and the server's name in `_meta`. `server/discover` lists the four versions it speaks, and any unsupported version gets 400 with `-32022` and that list. `initialize` still answers `2025-11-25`, `2025-06-18` and `2025-03-26`, and the token, Host and Origin checks come first as before. The stdio bridge mirrors a modern request's `_meta` into those headers, and a modern client's name shows in the MCP tab from `server/discover`. `checkRequest` and `mirrorHeaders` in `src/shared/mcp.js` (4 tests, and the bridge's test sends modern requests). *(roadmap: Upstream changes)*
- **MCP over stdio, id `houston`:** `scripts/mcp-stdio.js` bridges the app's HTTP server to stdio, reading `mcp.json` on every message, so Claude Code, Codex, opencode and Antigravity started in any terminal reach the app and survive its restarts; with the app closed every call answers "Houston isn't running". `serverInfo` now says `houston`; the userData folder keeps `ai-command-center` so saved data stays put. `tests/mcp-stdio.test.js` (1 test).
- **Agent work in the MCP tab:** every `terminal_run` and `cron_run` ask gets a row above the calls, newest first: the exact command or task name, where it goes (its folder, or the Cronsole task id) and how it stands: waiting for approval (the ask on the bar), queued behind it, running with its run id, finished or failed with the exit code, cancelled, denied, not answered in time, or withdrawn because its asker went away; a Cronsole task ends as started in Cronsole. Hover for when it was asked and ended. The tab's label counts what's waiting or running. The list lives in memory, newest 50, open work never dropped. The confirm bar's answer now reaches main as yes or no rather than yes or nothing, so a Deny shows as denied. `src/shared/activity.js` (3 tests); `npm run smoke` checks the success, the exit code 3 and the cancel each show with how they ended (33 checks). *(roadmap: Milestone D)*
